Hysteria2 counts each user's bytes and closes the connections of a user taken out of the users file (raycontrol docs/spec/traffic-limit-v1.md §2.2, §3.2); Yggdrasil clients are isolated: a device reaches the node only (raycontrol docs/spec/lan-v1.md §2). IPC and configs are as before; with an older rayd the node works as v0.14.1, Yggdrasil isolation included.

- Hysteria2: bytes by user. The line traffic on stats_socket, in place of an address, gets {"v":1,"boot":"<16 hex>","users":{"u5":{"up":123,"down":456}}} and the socket closes. up is what the node sent to destinations, down what it received from them and passed on to the client: streams and datagrams, the payload only, without Hysteria2's and QUIC's headers. A failed dial counts nothing. The counters run from the process's start, always on, and reading resets nothing; boot is random at each start, a new one means they began again. A name taken out of the users file keeps its counter until a restart (raycontrol counts by name). By name only: no destinations, addresses, ports or times; counters never go to the log. Cost: a stream or datagram session finds its user's counters once, in its context; a buffer costs an atomic add. The address queries are as before; another line still gets no answer, which is also what a niko-server before v0.15.0 gives traffic.
- Hysteria2: a reload of the users file (SIGHUP, or the file changed) closes at once the QUIC connections of a name no longer in it or disabled there (expired, switched off, over its limit) and of a name whose password changed, with all their streams and datagrams; the others stay. A password was checked once per connection: a user taken out stayed in for as long as its client kept the connection (keepalive every 25 s), so neither a limit nor an expiry ended anything. A connection whose password was checked against the old table while the reload ran is closed as well: its admission and the reload meet under one lock. The log says how many connections closed, not whose.
- sing-quic (third_party): the ConnectionHook also gets a way to close its connection. The service's user is a value per name and password rather than the name, which carries the name's counters.
- Yggdrasil: clients isolated (raycontrol docs/spec/lan-v1.md §2). The core carried ironwood frames between any two of its peers: one user's device reached another user's, and anyone's device through the node. The backend now copies each client's link frame by frame, after the handshake each way, as ironwood frames it (a uvarint length, then the type). Of traffic, pathNotify and pathBroken it reads the source and destination keys, as ironwood decodes them, and lets through from the client only its own key to the node's, and to the client only the node's key to its own; pathBroken goes back to the source of the traffic it reports on, so for it the two trade places. Lookups go to whoever might answer them: from the client any of its own (its key the source), to the client only the node's for what the client itself would answer (its key, or one from its address). A client that claimed every key in its bloom filter got the other clients' lookups for the node, and the node's lookups for each of them, full keys and all. Anything else of those four types is dropped without a word and counted; keepalives, the tree and the bloom filters pass as they are. Two leaks are left, known: the node's bloom filter to a client tells whether an address the client already knows is at the node (it lists nobody), and when a client's key is the least on the tree (no public peers), every client gets that key in the tree's announcements. A device reaches the node only: no data, no session and no answer about presence between two devices, of two users or of one; a frame with the node's key as its source goes no further than the client's link. The rule goes through a key's group, which no key has yet: LAN (lan-v1) adds groups later. A frame the core would refuse (longer than its largest, 131070 bytes; empty; one ironwood's decoders do not take) closes the link. Frames are held whole in pooled buffers, without an allocation per frame: in memory the copy runs at 14-20 GB/s where io.Copy ran at 26-38 GB/s, through unix sockets at 2.3-2.9 GB/s where io.Copy ran at 2.9-3.4 GB/s.
- Yggdrasil: the filter answers for the frames it drops (review of the isolation). An ironwood peer that sends a frame ends the link unless something comes back within 3 s, and one that gets a frame owes a keepalive that anything it sends pays. A dropped frame got nothing back: a client looking another up ended the idle one's link, traffic sprayed at the node's ports ended every idle client's link in 3 s, and with no one at fault, when the tree's root (a client) left, the node's stale paths led into another client's link, which dropped 120 frames, lost the paths for seconds and went down. Now, on the link where a frame is dropped: for a frame of the client's, the client gets a keepalive (01 01), the answer the node would have given, and the node, if it waits for an answer the dropped frame would have paid, a keepalive; for traffic to the client from or to the node, the core gets the pathBroken the client's ironwood sends for traffic it cannot pass on (the path the traffic's from as it came, the watermark ^uint64(0), the traffic's source and dest), which puts the node's stale path right, and the client, if it waits, a keepalive; for anything else to the client, the client gets a ping: a pathBroken from the node to it with an empty path and the watermark 0 (68 bytes), which its ironwood passes nowhere and drops, but answers with a keepalive to the node. Nothing is answered to the node for the client: a link whose client is gone without a word (its TCP dead, no reset) ends in 3 s, however often someone looks the client up. One answer per dropped frame, never on another link, a keepalive and a ping waiting once; writes are whole frames under one lock per side, the injected frames wait (16 KiB at most a side) for a goroutine of their own, so a drop never blocks.
- Yggdrasil: frames of a client's to the node (traffic and pathNotify to it, pathBroken back to it) get the watermark 0, written in place in as many bytes: the node takes them itself, as it would with a true path, whatever path the client put in them. A client steers nothing through its paths: no traffic sprayed at other clients' ports, nothing dropped for it, nothing told of which ports are taken.
- Yggdrasil: the core's ipv6rwc answered a packet over the MTU with a Packet Too Big, 512 bytes of the packet in it, to the packet's source address before checking that address against the sender's key: a device that put another's address as the source had the node send that device its bytes. Fixed in arngory/yggdrasil-go 5afe92f; the core comes from there.
- Yggdrasil: known and left as they are: two clients that agree can pass bits to each other through the bloom filters the node merges (8192 bits an update; through the node they have the internet anyway), and a link holds a buffer of the largest frame (131080 bytes) each way while a large frame comes in pieces.
- Yggdrasil: the core from arngory/yggdrasil-go 9ba3c0a, with DebugPrivacy on: remote getSelf, getPeers and getTree get no answer. getPeers listed the key of every connected device to anyone with a session to the node; NodeInfoPrivacy did not cover it.
- Yggdrasil: stats_socket (optional), one JSON line to whoever connects, as dnstt's: started, and dropped_frames, the frames the filter dropped in total. The filter writes nothing about frames to the log at any level: no keys, addresses or groups.
- The change is for every client, with LAN or without: a device no longer reaches another device through the node, even one of the same user. Nothing in Niko used it (lan-v1 §2.5, the client's answers in §7).

Hysteria2 считает байты каждого пользователя и закрывает соединения пользователя, снятого из файла пользователей (raycontrol docs/spec/traffic-limit-v1.md §2.2, §3.2); клиенты Yggdrasil изолированы: устройство достаёт только до ноды (raycontrol docs/spec/lan-v1.md §2). IPC и конфиги прежние; со старым rayd нода работает как v0.14.1, вместе с изоляцией Yggdrasil.

- Hysteria2: байты по пользователю. Строка traffic в stats_socket вместо адреса получает {"v":1,"boot":"<16 hex>","users":{"u5":{"up":123,"down":456}}}, и сокет закрывается. up — сколько нода отправила назначениям, down — сколько получила от них и отдала клиенту: потоки и датаграммы, только полезная нагрузка, без заголовков Hysteria2 и QUIC. Неудачный dial не считается. Счёт идёт с запуска процесса, всегда включён, чтение его не сбрасывает; boot случаен на каждый запуск, новый boot — счёт начался заново. Имя, снятое из файла пользователей, сохраняет счётчик до перезапуска (raycontrol считает по имени). Только по имени: ни назначений, ни адресов, ни портов, ни времени; счётчики в журнал не пишутся. Цена: поток или сессия датаграмм находит счётчики пользователя один раз, в своём контексте; буфер стоит одного атомарного сложения. Запросы по адресу прежние; на другую строку по-прежнему нет ответа — так же niko-server до v0.15.0 отвечает на traffic.
- Hysteria2: перечитывание файла пользователей (SIGHUP или изменение файла) сразу закрывает QUIC-соединения имени, которого в файле больше нет или которое там выключено (просрочено, выключено, исчерпало лимит), и имени со сменённым паролем, со всеми потоками и датаграммами; остальные не трогаются. Пароль проверялся раз на соединение: снятый пользователь оставался, пока клиент держит соединение (keepalive раз в 25 с), так что ни лимит, ни конец срока ничего не обрывали. Соединение, чей пароль сверялся со старой таблицей, пока шло перечитывание, тоже закрывается: его допуск и перечитывание встречаются под одной блокировкой. В журнале — сколько соединений закрыто, но не чьих.
- sing-quic (third_party): ConnectionHook получает ещё и способ закрыть своё соединение. Пользователь сервиса — значение на имя и пароль, а не имя; оно несёт счётчики имени.
- Yggdrasil: клиенты изолированы (raycontrol docs/spec/lan-v1.md §2). Ядро пересылало кадры ironwood между любыми двумя своими пирами: устройство одного пользователя доставало до устройства другого, а через ноду — до чьего угодно. Теперь бэкенд копирует линк каждого клиента по кадрам, после рукопожатия в каждую сторону, как их делит ironwood (длина uvarint, затем тип). В кадрах traffic, pathNotify и pathBroken он читает ключи источника и назначения, как их разбирает ironwood, и пропускает от клиента только его ключ к ключу ноды, а к клиенту — только ключ ноды к его ключу; pathBroken идёт обратно к источнику трафика, о котором сообщает, поэтому у него они меняются ролями. Lookup идёт всем, кто может на него ответить: от клиента — любой его собственный (источник — его ключ), к клиенту — только lookup ноды того, на что клиент ответил бы сам (его ключ или ключ из его адреса). Клиент, объявивший в bloom-фильтре все ключи, получал lookup других клиентов к ноде и lookup ноды к каждому из них — с полными ключами. Остальные кадры этих четырёх типов молча отбрасываются и считаются; keepalive, дерево и bloom-фильтры проходят как есть. Остаются две известные утечки: bloom-фильтр ноды к клиенту говорит, на ноде ли адрес, который клиент уже знает (но никого не перечисляет), а когда ключ клиента — наименьший на дереве (нет публичных пиров), этот ключ получают в анонсах дерева все клиенты. Устройство достаёт только до ноды: между двумя устройствами — разных пользователей или одного — нет ни данных, ни сессий, ни ответов о присутствии; кадр с ключом ноды в источнике дальше линка клиента не идёт. Правило идёт через группу ключа, которой пока нет ни у кого: группы добавит LAN (lan-v1). Кадр, который ядро не приняло бы (длиннее самого большого, 131070 байт; пустой; не разбирается декодерами ironwood), закрывает линк. Кадры держатся целиком в буферах из пула, без выделения памяти на кадр: в памяти копирование идёт на 14–20 ГБ/с против 26–38 ГБ/с у io.Copy, через unix-сокеты — 2,3–2,9 ГБ/с против 2,9–3,4 ГБ/с.
- Yggdrasil: за отброшенные кадры отвечает фильтр (ревью изоляции). Пир ironwood, пославший кадр, рвёт линк, если за 3 с ничего не пришло в ответ, а получивший кадр должен keepalive, который гасит любой его кадр. На отброшенный кадр ответа не было: клиент, искавший другого, рвал линк простаивающего; трафик, разосланный по портам ноды, за 3 с рвал линки всех простаивающих клиентов; а без всякого злого умысла, когда уходил корень дерева (клиент), устаревшие пути ноды вели в линк другого клиента — 120 отброшенных кадров, пути пропадали на секунды, линк падал. Теперь на линке, где кадр отброшен: за кадр клиента клиент получает keepalive (01 01), ответ, какой дала бы нода, а нода, если ждёт ответа, который погасил бы отброшенный кадр, — keepalive; за traffic к клиенту от ноды или к ней ядро получает pathBroken, какой послал бы ironwood клиента за трафик, который некуда передать (путь — from трафика как есть, водяной знак ^uint64(0), источник и назначение трафика); он чинит устаревший путь ноды, а клиент, если ждёт ответа, получает keepalive; за остальное к клиенту клиент получает «пинг»: pathBroken от ноды к нему с пустым путём и водяным знаком 0 (68 байт), который его ironwood никуда не передаёт и отбрасывает, но отвечает за него ноде keepalive. За клиента ноде не отвечают: линк, чей клиент пропал молча (TCP умер без сброса), рвётся за 3 с, как часто клиента ни ищи. Один ответ на отброшенный кадр и никогда на чужом линке, keepalive и пинг ждут по одному; запись — целыми кадрами под одним замком на сторону, вставленные кадры ждут (не больше 16 КиБ на сторону) своей горутины, так что отбрасывающий никогда не ждёт.
- Yggdrasil: кадры клиента к ноде (traffic и pathNotify к ней, pathBroken назад к ней) получают водяной знак 0, записанный на месте в то же число байт: нода берёт их сама, как с верным путём, какой бы путь ни поставил клиент. Путями клиент ничего не направляет: ни трафик по портам других клиентов, ни отбросов из-за него, ни сведений о том, какие порты заняты.
- Yggdrasil: ipv6rwc ядра отвечал на пакет больше MTU сообщением Packet Too Big с 512 байтами пакета на адрес источника, ещё не сверив его с ключом отправителя: устройство, подставившее адрес другого, получало от ноды пересылку своих байтов этому другому. Исправлено в arngory/yggdrasil-go 5afe92f; ядро — оттуда.
- Yggdrasil: известно и оставлено как есть: два сговорившихся клиента могут передавать друг другу биты через bloom-фильтры, которые нода сливает (8192 бита на обновление; через ноду у них и так есть интернет), а линк держит буфер самого большого кадра (131 080 байт) на сторону, пока большой кадр приходит по частям.
- Yggdrasil: ядро из arngory/yggdrasil-go 9ba3c0a, с включённым DebugPrivacy: на удалённые getSelf, getPeers и getTree ответа нет. getPeers отдавал ключи всех подключённых устройств любому, у кого есть сессия с нодой; NodeInfoPrivacy этого не закрывал.
- Yggdrasil: stats_socket (необязательно) — одна строка JSON каждому, кто подключится, как у dnstt: started и dropped_frames, всего кадров, отброшенных фильтром. О кадрах фильтр ничего не пишет в журнал ни на каком уровне: ни ключей, ни адресов, ни групп.
- Изменение для всех клиентов, с LAN и без: устройство больше не достаёт через ноду до другого устройства, даже того же пользователя. В Niko этим ничто не пользовалось (lan-v1 §2.5, ответы клиента в §7).
