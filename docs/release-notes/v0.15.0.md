Hysteria2 counts each user's bytes and closes the connections of a user taken out of the users file (raycontrol docs/spec/traffic-limit-v1.md §2.2, §3.2); Yggdrasil clients are isolated: a device reaches the node only (raycontrol docs/spec/lan-v1.md §2). IPC and configs are as before; with an older rayd the node works as v0.14.1, Yggdrasil isolation included.

- Hysteria2: bytes by user. The line traffic on stats_socket, in place of an address, gets {"v":1,"boot":"<16 hex>","users":{"u5":{"up":123,"down":456}}} and the socket closes. up is what the node sent to destinations, down what it received from them and passed on to the client: streams and datagrams, the payload only, without Hysteria2's and QUIC's headers. A failed dial counts nothing. The counters run from the process's start, always on, and reading resets nothing; boot is random at each start, a new one means they began again. A name taken out of the users file keeps its counter until a restart (raycontrol counts by name). By name only: no destinations, addresses, ports or times; counters never go to the log. Cost: a stream or datagram session finds its user's counters once, in its context; a buffer costs an atomic add. The address queries are as before; another line still gets no answer, which is also what a niko-server before v0.15.0 gives traffic.
- Hysteria2: a reload of the users file (SIGHUP, or the file changed) closes at once the QUIC connections of a name no longer in it or disabled there (expired, switched off, over its limit) and of a name whose password changed, with all their streams and datagrams; the others stay. A password was checked once per connection: a user taken out stayed in for as long as its client kept the connection (keepalive every 25 s), so neither a limit nor an expiry ended anything. A connection whose password was checked against the old table while the reload ran is closed as well: its admission and the reload meet under one lock. The log says how many connections closed, not whose.
- sing-quic (third_party): the ConnectionHook also gets a way to close its connection. The service's user is a value per name and password rather than the name, which carries the name's counters.
- Yggdrasil: clients isolated (raycontrol docs/spec/lan-v1.md §2). The core carried ironwood frames between any two of its peers: one user's device reached another user's, and anyone's device through the node. The backend now copies each client's link frame by frame, after the handshake each way, as ironwood frames it (a uvarint length, then the type). Of traffic, pathNotify and pathBroken it reads the source and destination keys, as ironwood decodes them, and lets through from the client only its own key to the node's, and to the client only the node's key to its own; pathBroken goes back to the source of the traffic it reports on, so for it the two trade places. Lookups go to whoever might answer them: from the client any of its own (its key the source), to the client only the node's for what the client itself would answer (its key, or one from its address). A client that claimed every key in its bloom filter got the other clients' lookups for the node, and the node's lookups for each of them, full keys and all. Anything else of those four types is dropped without a word and counted; keepalives, the tree and the bloom filters pass as they are. Two leaks are left, known: the node's bloom filter to a client tells whether an address the client already knows is at the node (it lists nobody), and when a client's key is the least on the tree (no public peers), every client gets that key in the tree's announcements. A device reaches the node only: no data, no session and no answer about presence between two devices, of two users or of one; a frame with the node's key as its source goes no further than the client's link. The rule goes through a key's group, which no key has yet: LAN (lan-v1) adds groups later. A frame the core would refuse (longer than its largest, 131070 bytes; empty; one ironwood's decoders do not take) closes the link. Frames are held whole in pooled buffers, without an allocation per frame: in memory the copy runs at 12-20 GB/s where io.Copy ran at 20-36 GB/s, through unix sockets at 2.3-2.9 GB/s where io.Copy ran at 2.9-3.4 GB/s.
- Yggdrasil: the core from arngory/yggdrasil-go 9ba3c0a, with DebugPrivacy on: remote getSelf, getPeers and getTree get no answer. getPeers listed the key of every connected device to anyone with a session to the node; NodeInfoPrivacy did not cover it.
- Yggdrasil: stats_socket (optional), one JSON line to whoever connects, as dnstt's: started, and dropped_frames, the frames the filter dropped in total. The filter writes nothing about frames to the log at any level: no keys, addresses or groups.
- The change is for every client, with LAN or without: a device no longer reaches another device through the node, even one of the same user. Nothing in Niko used it (lan-v1 §2.5, the client's answers in §7).

Hysteria2 считает байты каждого пользователя и закрывает соединения пользователя, снятого из файла пользователей (raycontrol docs/spec/traffic-limit-v1.md §2.2, §3.2); клиенты Yggdrasil изолированы: устройство достаёт только до ноды (raycontrol docs/spec/lan-v1.md §2). IPC и конфиги прежние; со старым rayd нода работает как v0.14.1, вместе с изоляцией Yggdrasil.

- Hysteria2: байты по пользователю. Строка traffic в stats_socket вместо адреса получает {"v":1,"boot":"<16 hex>","users":{"u5":{"up":123,"down":456}}}, и сокет закрывается. up — сколько нода отправила назначениям, down — сколько получила от них и отдала клиенту: потоки и датаграммы, только полезная нагрузка, без заголовков Hysteria2 и QUIC. Неудачный dial не считается. Счёт идёт с запуска процесса, всегда включён, чтение его не сбрасывает; boot случаен на каждый запуск, новый boot — счёт начался заново. Имя, снятое из файла пользователей, сохраняет счётчик до перезапуска (raycontrol считает по имени). Только по имени: ни назначений, ни адресов, ни портов, ни времени; счётчики в журнал не пишутся. Цена: поток или сессия датаграмм находит счётчики пользователя один раз, в своём контексте; буфер стоит одного атомарного сложения. Запросы по адресу прежние; на другую строку по-прежнему нет ответа — так же niko-server до v0.15.0 отвечает на traffic.
- Hysteria2: перечитывание файла пользователей (SIGHUP или изменение файла) сразу закрывает QUIC-соединения имени, которого в файле больше нет или которое там выключено (просрочено, выключено, исчерпало лимит), и имени со сменённым паролем, со всеми потоками и датаграммами; остальные не трогаются. Пароль проверялся раз на соединение: снятый пользователь оставался, пока клиент держит соединение (keepalive раз в 25 с), так что ни лимит, ни конец срока ничего не обрывали. Соединение, чей пароль сверялся со старой таблицей, пока шло перечитывание, тоже закрывается: его допуск и перечитывание встречаются под одной блокировкой. В журнале — сколько соединений закрыто, но не чьих.
- sing-quic (third_party): ConnectionHook получает ещё и способ закрыть своё соединение. Пользователь сервиса — значение на имя и пароль, а не имя; оно несёт счётчики имени.
- Yggdrasil: клиенты изолированы (raycontrol docs/spec/lan-v1.md §2). Ядро пересылало кадры ironwood между любыми двумя своими пирами: устройство одного пользователя доставало до устройства другого, а через ноду — до чьего угодно. Теперь бэкенд копирует линк каждого клиента по кадрам, после рукопожатия в каждую сторону, как их делит ironwood (длина uvarint, затем тип). В кадрах traffic, pathNotify и pathBroken он читает ключи источника и назначения, как их разбирает ironwood, и пропускает от клиента только его ключ к ключу ноды, а к клиенту — только ключ ноды к его ключу; pathBroken идёт обратно к источнику трафика, о котором сообщает, поэтому у него они меняются ролями. Lookup идёт всем, кто может на него ответить: от клиента — любой его собственный (источник — его ключ), к клиенту — только lookup ноды того, на что клиент ответил бы сам (его ключ или ключ из его адреса). Клиент, объявивший в bloom-фильтре все ключи, получал lookup других клиентов к ноде и lookup ноды к каждому из них — с полными ключами. Остальные кадры этих четырёх типов молча отбрасываются и считаются; keepalive, дерево и bloom-фильтры проходят как есть. Остаются две известные утечки: bloom-фильтр ноды к клиенту говорит, на ноде ли адрес, который клиент уже знает (но никого не перечисляет), а когда ключ клиента — наименьший на дереве (нет публичных пиров), этот ключ получают в анонсах дерева все клиенты. Устройство достаёт только до ноды: между двумя устройствами — разных пользователей или одного — нет ни данных, ни сессий, ни ответов о присутствии; кадр с ключом ноды в источнике дальше линка клиента не идёт. Правило идёт через группу ключа, которой пока нет ни у кого: группы добавит LAN (lan-v1). Кадр, который ядро не приняло бы (длиннее самого большого, 131070 байт; пустой; не разбирается декодерами ironwood), закрывает линк. Кадры держатся целиком в буферах из пула, без выделения памяти на кадр: в памяти копирование идёт на 12–20 ГБ/с против 20–36 ГБ/с у io.Copy, через unix-сокеты — 2,3–2,9 ГБ/с против 2,9–3,4 ГБ/с.
- Yggdrasil: ядро из arngory/yggdrasil-go 9ba3c0a, с включённым DebugPrivacy: на удалённые getSelf, getPeers и getTree ответа нет. getPeers отдавал ключи всех подключённых устройств любому, у кого есть сессия с нодой; NodeInfoPrivacy этого не закрывал.
- Yggdrasil: stats_socket (необязательно) — одна строка JSON каждому, кто подключится, как у dnstt: started и dropped_frames, всего кадров, отброшенных фильтром. О кадрах фильтр ничего не пишет в журнал ни на каком уровне: ни ключей, ни адресов, ни групп.
- Изменение для всех клиентов, с LAN и без: устройство больше не достаёт через ноду до другого устройства, даже того же пользователя. В Niko этим ничто не пользовалось (lan-v1 §2.5, ответы клиента в §7).
