Hysteria2 counts each user's bytes for raycontrol's traffic limits and closes the connections of a user taken out of the users file (raycontrol docs/spec/traffic-limit-v1.md §2.2, §3.2). IPC and configs are as before; with an older rayd the node works as v0.14.1.

- Hysteria2: bytes by user. The line traffic on stats_socket, in place of an address, gets {"v":1,"boot":"<16 hex>","users":{"u5":{"up":123,"down":456}}} and the socket closes. up is what the node sent to destinations, down what it received from them and passed on to the client: streams and datagrams, the payload only, without Hysteria2's and QUIC's headers. A failed dial counts nothing. The counters run from the process's start, always on, and reading resets nothing; boot is random at each start, a new one means they began again. A name taken out of the users file keeps its counter until a restart (raycontrol counts by name). By name only: no destinations, addresses, ports or times; counters never go to the log. Cost: a stream or datagram session finds its user's counters once, in its context; a buffer costs an atomic add. The address queries are as before; another line still gets no answer, which is also what a niko-server before v0.15.0 gives traffic.
- Hysteria2: a reload of the users file (SIGHUP, or the file changed) closes at once the QUIC connections of a name no longer in it or disabled there (expired, switched off, over its limit) and of a name whose password changed, with all their streams and datagrams; the others stay. A password was checked once per connection: a user taken out stayed in for as long as its client kept the connection (keepalive every 25 s), so neither a limit nor an expiry ended anything. A connection whose password was checked against the old table while the reload ran is closed as well: its admission and the reload meet under one lock. The log says how many connections closed, not whose.
- sing-quic (third_party): the ConnectionHook also gets a way to close its connection. The service's user is a value per name and password rather than the name, which carries the name's counters.

Hysteria2 считает байты каждого пользователя для лимитов трафика raycontrol и закрывает соединения пользователя, снятого из файла пользователей (raycontrol docs/spec/traffic-limit-v1.md §2.2, §3.2). IPC и конфиги прежние; со старым rayd нода работает как v0.14.1.

- Hysteria2: байты по пользователю. Строка traffic в stats_socket вместо адреса получает {"v":1,"boot":"<16 hex>","users":{"u5":{"up":123,"down":456}}}, и сокет закрывается. up — сколько нода отправила назначениям, down — сколько получила от них и отдала клиенту: потоки и датаграммы, только полезная нагрузка, без заголовков Hysteria2 и QUIC. Неудачный dial не считается. Счёт идёт с запуска процесса, всегда включён, чтение его не сбрасывает; boot случаен на каждый запуск, новый boot — счёт начался заново. Имя, снятое из файла пользователей, сохраняет счётчик до перезапуска (raycontrol считает по имени). Только по имени: ни назначений, ни адресов, ни портов, ни времени; счётчики в журнал не пишутся. Цена: поток или сессия датаграмм находит счётчики пользователя один раз, в своём контексте; буфер стоит одного атомарного сложения. Запросы по адресу прежние; на другую строку по-прежнему нет ответа — так же niko-server до v0.15.0 отвечает на traffic.
- Hysteria2: перечитывание файла пользователей (SIGHUP или изменение файла) сразу закрывает QUIC-соединения имени, которого в файле больше нет или которое там выключено (просрочено, выключено, исчерпало лимит), и имени со сменённым паролем, со всеми потоками и датаграммами; остальные не трогаются. Пароль проверялся раз на соединение: снятый пользователь оставался, пока клиент держит соединение (keepalive раз в 25 с), так что ни лимит, ни конец срока ничего не обрывали. Соединение, чей пароль сверялся со старой таблицей, пока шло перечитывание, тоже закрывается: его допуск и перечитывание встречаются под одной блокировкой. В журнале — сколько соединений закрыто, но не чьих.
- sing-quic (third_party): ConnectionHook получает ещё и способ закрыть своё соединение. Пользователь сервиса — значение на имя и пароль, а не имя; оно несёт счётчики имени.
