Draft for raycontrol v0.14.

- The DNS front's own answers (the apex, the probe, a truncated answer) and dnstt's carry the query's DO bit, as RFC 3225 §3 asks and other servers answer: always 0 was a mark of the tunnel on the way between a resolver and the node.
- dnstt: stats_socket gives the backend's counters as one JSON line to whoever connects (dnsttserver.StatsSnapshot): the backend's start, by which a reader tells a restart, queries, retries from the memo, sessions and handshakes now, sessions admitted, session starts refused (full, rate, a device's bound; by start packet, so a client's retries count again), evicted, handshakes timed out, streams refused, and the dnsauth-v1 and dnsseal-v1 counters (valid, untagged, refused, throttled; opened, open taken, open refused). raycontrol puts them in its metrics.

- dnstt: options.zones, spare zones of the same tunnel (raycontrol docs/spec/dnszones-v1.md): a query in any of them is the tunnel's, keys, seal and tags shared; up to 4, each a DNS name of 253 characters at most, none twice, none nested in another. The front routes each zone to the backend as it routes the main one; give each the main zone's ns, probe and seal_pad.
- check refuses nested zones in dns.zones[] too (a name under both was the first listed zone's, while dnstt took the longest) and zone names over 253 characters (they passed check and stopped the backend at its start).
- dnstt compares a query's zone without copies: with several zones a query took 14 allocations. The front reads a query's name with one copy (1.1 µs and 9 allocations a query before, 0.26 µs and 1 now), folding ASCII case only (RFC 4343); a name over 253 characters, or with a dot inside a label, is no query it passes on.
- The DNS front: dns.stats_socket gives its counters the same way (DNSFrontSnapshot): queries by zone (load: anyone can send a zone's name), refused outside the zones, apex answers, probes answered and over the rate, queries queued for a backend and not (the backend away or its queue full), the backends' answers sent (truncated ones among them), unmatched and dropped, and datagrams that are no query. A query the front could not pass on no longer waits for an answer.
- dnstt with dnsauth counts each zone's queries with a device's valid tag (zones in its stats): which zone of the tunnel clients reach, which no one without a device's key can make up.
- A stats socket that cannot be made is said in the log and left out: it no longer stops the front (and its TCP and UDP 443) or the backend; an accept error other than the socket's close no longer ends it. A stats socket on a backend's socket, the inner stage's or the probe key's path is refused by check.
- check refuses a zone name that only folds into ASCII (a Kelvin sign for k: it passed and the zone was dead), masterdns zones twice, nested or over 253 characters, and entries of one backend in dns.zones with different probe, seal_pad or ns. A query name with a dot inside a label is answered REFUSED, as names outside the zones are, instead of no answer.
- CI tests the vendored dnstt's dns package, which niko changes.
- masterdns from the client's fork 34d5ef9: sealed answers (mdseal-v1, options.seal) and a device's tag in every query (dnsauth for masterdns: options.auth, auth_keys_file, auth_scan_hmacs, the keys file as dnstt's). A session is bound to its device; required refuses whoever holds only the link (the service's key is in every link). The scan for queries no session explains has its budget split: 40 % MTU probes, 40 % SESSION_INITs, 20 % queries to sessions the server has no record of, the 64 devices found last first. Off unless set. The fork also stops PONG and ERROR_DROP carrying a counter, keeps base64 after a session's reset, and no longer ends a session for another's ERROR_DROP.

Черновик для raycontrol v0.14.

- Собственные ответы DNS-фронта (вершина зоны, проба, урезанный ответ) и ответы dnstt несут бит DO запроса, как требует RFC 3225 §3 и как отвечают другие серверы: всегда 0 было приметой туннеля на пути между резолвером и нодой.
- dnstt: stats_socket отдаёт счётчики бэкенда одной строкой JSON каждому, кто подключится (dnsttserver.StatsSnapshot): время старта бэкенда (по нему видно перезапуск), запросы, повторы из памяти, сессии и рукопожатия сейчас, допущенные сессии, отказы началам сессий (мест нет, темп, предел устройства; по пакетам начала, повторы клиента считаются снова), вытесненные, рукопожатия по сроку, отказы потокам, счётчики dnsauth-v1 и dnsseal-v1 (верные, без метки, отказано, сверх бюджета; вскрыто, открытых принято, открытых отказано). raycontrol кладёт их в свои метрики.
- dnstt: options.zones — запасные зоны того же туннеля (raycontrol docs/spec/dnszones-v1.md): запрос в любой из них — запрос туннеля, ключи, печать и метки общие; до 4 зон, каждая — DNS-имя не длиннее 253 символов, без повторов и без вложенных одна в другую. Фронт направляет каждую зону на бэкенд, как основную; каждой — те же ns, probe и seal_pad, что у основной.
- check отвергает вложенные зоны и в dns.zones[] (имя под обеими доставалось первой в списке, а dnstt брал самую длинную) и имена зон длиннее 253 символов (проходили check и останавливали бэкенд при старте).
- dnstt сравнивает зону запроса без копий: с несколькими зонами запрос стоил 14 выделений памяти. Фронт читает имя запроса одной копией (было 1,1 мкс и 9 выделений на запрос, стало 0,26 мкс и одно), регистр сворачивает только у ASCII (RFC 4343); имя длиннее 253 символов или с точкой внутри метки — не запрос, который он передаёт дальше.
- DNS-фронт: dns.stats_socket отдаёт его счётчики так же (DNSFrontSnapshot): запросы по зонам (нагрузка: имя зоны может прислать кто угодно), отказы вне зон, ответы вершины, пробы отвеченные и сверх темпа, запросы, поставленные в очередь бэкенда и нет (бэкенд не на связи или очередь полна), ответы бэкендов отправленные (среди них урезанные), без ждущего запроса и не отправленные, датаграммы, которые не запрос. Запрос, который фронт не смог передать, больше не ждёт ответа.
- dnstt с dnsauth считает по каждой зоне запросы с верной меткой устройства (zones в его счётчиках): до какой зоны туннеля доходят клиенты — подделать это без ключа устройства нельзя.
- Сокет счётчиков, который не создаётся, — предупреждение в журнале и без счётчиков: он больше не останавливает фронт (а с ним TCP и UDP 443) или бэкенд; ошибка accept, кроме закрытия сокета, его больше не гасит. Сокет счётчиков на пути сокета бэкенда, внутренней ступени или ключа пробы check отвергает.
- check отвергает имя зоны, которое становится ASCII только после свёртки регистра (знак Кельвина вместо k: проходило, а зона была мёртвой), зоны masterdns дважды, вложенные или длиннее 253 символов, и записи одного бэкенда в dns.zones с разными probe, seal_pad или ns. Запрос с точкой внутри метки получает REFUSED, как имена вне зон, а не тишину.
- CI гоняет тесты пакета dns у dnstt из third_party, который niko меняет.
- masterdns из форка клиента 34d5ef9: запечатанные ответы (mdseal-v1, options.seal) и метка устройства в каждом запросе (dnsauth для masterdns: options.auth, auth_keys_file, auth_scan_hmacs, файл ключей как у dnstt). Сессия привязана к своему устройству; required отказывает тому, у кого есть только ссылка (ключ сервиса — в каждой ссылке). Перебор для запросов без сессии — в бюджете по видам: 40 % пробам MTU, 40 % SESSION_INIT, 20 % запросам к сессиям, о которых нет записи; первыми — 64 недавно найденных устройства. По умолчанию выключено. Ещё форк убирает счётчик из PONG и ERROR_DROP, сохраняет base64 после сброса сессии и больше не рвёт сессию из-за чужого ERROR_DROP.
