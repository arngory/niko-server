- DNS front: backends.<name>.devices (raycontrol docs/spec/slipstream-v1.md §3). For a tagged zone's backend the front sends each query in IPC version 2, "NU" | 2 | client | local | device (8) | DNS (docs/IPC.md), the device a token of the one whose tag it checked: the first 8 bytes of SHA-256 of "niko-server device\0" and its ID, the same for all its queries, the ID not given away. The answers stay in version 1. slipstream-server server-v0.2.0 counts a device's connections by it (--max-connections-per-device): one device's key took every connection of the server. check: devices only on a backend in mode packet whose zones are all tagged and that no UDP route uses; an older slipstream server takes no version 2.
- check: two backends with the same socket are refused: a second name for it would take traffic past the first one's rules (devices, tags).

- DNS-фронт: backends.<имя>.devices (raycontrol docs/spec/slipstream-v1.md §3). Бэкенду зоны с меткой фронт шлёт каждый запрос в IPC версии 2, "NU" | 2 | client | local | device (8) | DNS (docs/IPC.md), где device — жетон устройства, чью метку он проверил: первые 8 байт SHA-256 от "niko-server device\0" и его id, один для всех его запросов, сам id не виден. Ответы остаются в версии 1. slipstream-server server-v0.2.0 считает по нему соединения устройства (--max-connections-per-device): ключ одного устройства занимал все соединения сервера. check: devices — только у бэкенда в режиме packet, все зоны которого с меткой и который не стоит в маршрутах UDP; более старый сервер slipstream версию 2 не берёт.
- check: два бэкенда с одним сокетом не принимаются: второе имя для него пускало бы трафик в обход правил первого (devices, метки).
