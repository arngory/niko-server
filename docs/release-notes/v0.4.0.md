- Backend yggdrasil: clients peer with the node directly over a tls:// link that tcpmux hands over by SNI (mode fd); TLS 1.3 with X25519MLKEM768 only
- A link is let in only with a key from users_file (yggdrasil.public_key) and a valid handshake signature; the file is reloaded on SIGHUP and when it changes, and links of removed keys close at once
- The yggdrasil-go core (the fork in arngory/sing-box/third_party) takes the links through a unix socket only the backend reaches; the node peers with nobody else unless peers are given
- The node's mesh address carries TCP on exit_ports to inner (a gVisor stack, keepalives on); other ports get a reset, UDP nothing
- Anything on the Yggdrasil name that is not a link gets the site's answer: an empty 404 in h2 or HTTP/1.1
- The binary grows by about 5 MB (yggdrasil-go and gVisor)

- Бэкенд yggdrasil: клиенты подключаются к ноде напрямую по tls-линку, который tcpmux отдаёт по SNI (режим fd); TLS 1.3 только с X25519MLKEM768
- Линк впускается только с ключом из users_file (yggdrasil.public_key) и верной подписью рукопожатия; файл перечитывается по SIGHUP и при изменении, линки удалённых ключей закрываются сразу
- Ядро yggdrasil-go (форк в arngory/sing-box/third_party) получает линки через unix-сокет, доступный только бэкенду; ни с кем больше нода не соединяется, если не заданы peers
- Адрес узла в mesh передаёт TCP с exit_ports в inner (стек gVisor, с keepalive); на другие порты — сброс, UDP отбрасывается
- Всё, что приходит на имя Yggdrasil и не является линком, получает ответ сайта: пустой 404 по h2 или HTTP/1.1
- Бинарник вырос примерно на 5 МБ (yggdrasil-go и gVisor)
