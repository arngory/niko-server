The DNS front checks the device's tag of slipstream queries itself; the masterdns service key changes while it runs.

- DNS front: dns.zones[].tag "slipstream" with auth_keys_file (raycontrol docs/spec/slipstream-v1.md §2). The front decodes each query's data (base32 before the zone), finds the device's key by the dnsauth-v2 hint, checks the tag over the QUIC packet, and passes the query to the backend rebuilt (header, the question as it came, an OPT without options) only when it holds. Anything else gets NOERROR without records and never reaches the server (stats: untagged), with an OPT as the server's empty answer has (4096, the query's DO) when the query had one: the two read the same; another opcode than QUERY gets NOTIMP, as dnstt answers it. Only canonical base32 is taken (letters and 2-7, dots anywhere, whole bytes, the last character's spare bits zero), so the tag is checked over the bytes the server reads. A field that passed before is a copy (anyone on the path could replay a query while its tag holds, and the server sent the connection's next packet to the copy's address): the front remembers the fields four epochs, one memory per backend, and answers copies NOERROR, or nothing within 5 s of the original (a resolver's retry, whose original's answer is on its way) (stats: replayed). A generation holds 524288 fields, the whole window up to ~870 queries a second; past that a full one starts the next early (stats: replay_turns) and the server catches older copies. A query that never reached the backend allows one retry within 10 s. A keys file that does not read leaves the zone without keys, logged, instead of stopping the front. A backend's zones are all tagged with the same keys or none. The backend is the fork's slipstream server (arngory/slipstream, --front-socket) in mode packet.
- DNS front: REFUSED to a name outside the zones carries an OPT when the query had one (RFC 6891 §7).
- dnsauth-v2: a clock stepped back no longer builds the hint index on every lookup (3 ms a query with 2000 keys); the previous epoch's index is kept for a clock one epoch behind.
- masterdns: the service key changes while the server runs (raycontrol docs/spec/masterdns-key-rotation.md): encryption_key_file holds one key a line, the current first, then the previous one while it is still taken; the file is reread every 5 s by content. A changed file is taken once it reads the same on two ticks in a row (a file caught while written in place would close the previous key's sessions). A session stays on the key of its SESSION_INIT; the sessions of a key gone are closed at once. From the client's fork at f0eadfa (embed.NewServer, SetKeys), which also tags with dnsauth-v2; a nonce is remembered with the service key its query opened with (an INIT sealed anew under the other key is not a copy), and a session's stream cleanup is set under the store's lock.

DNS-фронт сам проверяет метку устройства в запросах slipstream; ключ сервиса masterdns меняется на ходу.

- DNS-фронт: dns.zones[].tag "slipstream" с auth_keys_file (raycontrol docs/spec/slipstream-v1.md §2). Фронт разбирает данные запроса (base32 перед зоной), находит ключ устройства по подсказке dnsauth-v2, проверяет метку над пакетом QUIC и только тогда передаёт запрос бэкенду пересобранным (заголовок, вопрос как пришёл, OPT без опций). Остальное получает NOERROR без записей и до сервера не доходит (счётчик untagged), с OPT, как у пустого ответа сервера (4096, DO запроса), если он был в запросе: ответы не отличить; другой opcode, чем QUERY, — NOTIMP, как у dnstt. Берётся только каноничный base32 (буквы и 2–7, точки где угодно, целые байты, лишние биты последнего символа нулевые), так что метка проверяется над теми байтами, что прочтёт сервер. Поле, которое уже прошло, — копия (любой на пути мог повторять запрос, пока держится метка, а сервер отправлял следующий пакет соединения на адрес копии): фронт помнит поля четыре эпохи, одна память на бэкенд, и отвечает на копии NOERROR, а в первые 5 с после оригинала — ничем (повтор резолвера, ответ оригинала уже в пути) (счётчик replayed). В поколении 524 288 полей — всё окно до ~870 запросов в секунду; дальше полное поколение начинает следующее раньше (счётчик replay_turns), и копии старше ловит сервер. Запрос, не дошедший до бэкенда, разрешает один повтор в течение 10 с. Файл ключей, который не читается, оставляет зону без ключей с записью в журнале, а не останавливает фронт. Зоны одного бэкенда — все с одной меткой и ключами или все без. Бэкенд — сервер slipstream из форка (arngory/slipstream, --front-socket) в режиме packet.
- DNS-фронт: REFUSED на имя вне зон несёт OPT, если он был в запросе (RFC 6891 §7).
- dnsauth-v2: часы, отведённые назад, больше не строят указатель подсказок на каждый поиск (3 мс на запрос при 2000 ключей); указатель прошлой эпохи держится для часов, отстающих на эпоху.
- masterdns: ключ сервиса меняется, пока сервер работает (raycontrol docs/spec/masterdns-key-rotation.md): в encryption_key_file по ключу на строку, первым текущий, следом прежний, пока он принимается; файл перечитывается раз в 5 с по содержимому. Изменённый файл берётся, когда два тика подряд читают одно и то же (файл, пойманный посреди записи на месте, закрыл бы сессии прежнего ключа). Сессия остаётся на ключе своего SESSION_INIT; сессии снятого ключа закрываются сразу. Из форка клиента f0eadfa (embed.NewServer, SetKeys), который также подписывает по dnsauth-v2; nonce запоминается вместе с ключом сервиса, которым открыт его запрос (INIT, запечатанный заново другим ключом, — не копия), а очистка потоков сессии задаётся под замком хранилища.
