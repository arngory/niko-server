- dnstt, dnsauth-v1: a query without a valid tag gets NXDOMAIN before anything of dnstt's own, so an EDNS size under 1232 no longer draws dnstt's FORMERR from a probe
- dnstt, dnsauth-v1: each key's HMAC is made once, with no allocation per query; the current epoch is tried first; a garbage query with 100 devices costs about 93 µs instead of 245 µs
- dnstt, dnsauth-v1: full key scans have a budget in HMACs (100000 a second, or 20 full scans of all devices, never under two; option auth_scan_hmacs). Over it a query of no known session gets NXDOMAIN; known sessions go on. The first 8 bytes of a query no key explained are remembered and looked at again only for 30 s, so old untagged clients cost nothing and a tag copied into garbage refuses neither the session nor its first query
- dnstt, dnsauth-v1: a keys reload keeps the session cache; a device id may have two keys (while one is replaced); the counters are logged hourly
- Hysteria2: QUIC idle timeout 60 s instead of 30, so a client's 25 s keepalive is not halved to 15 s (Niko 1.28)
- Hysteria2 salamander: the XOR as 64-bit words over each 32-byte block, 92 ns instead of 288 ns for a full packet; read buffers of 2 KiB; with salamander QUIC starts at 1272 bytes so the front, which sends with DF set, stays at 1280
- UDP front: an unknown flow is checked for salamander by opening 7 bytes on the stack, not a copy of the whole datagram
