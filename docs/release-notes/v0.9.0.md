The DNS front answers the zone apex of dnstt zones. For raycontrol v0.12.

- DNS front: dns.zones[].ns. With the names a zone is delegated to, the front answers at the zone's apex itself: SOA and NS as records, any other type NOERROR with no record and the SOA in authority (RFC 2308). Some resolvers gave SERVFAIL for a delegated zone whose apex had neither. The answers are built as dnstt's (QR and AA, the question as asked, OPT 4096 when the query had one), so the names go to dnstt zones only. A query not of class IN, not a QUERY or with an EDNS version other than 0 goes to the backend as before.
- Tests: the apex answers, also parsed by dnspython; the SOA through the real front beside a dnstt backend with dnsauth required.

DNS-фронт отвечает на вершине зон dnstt. Для raycontrol v0.12.

- DNS-фронт: dns.zones[].ns. С именами, на которые делегирована зона, фронт сам отвечает на её вершине: SOA и NS — записями, на любой другой тип — NOERROR без записей и с SOA в authority (RFC 2308). Часть резолверов без SOA и NS у вершины делегированной зоны давала SERVFAIL. Ответы собраны как ответы dnstt (QR и AA, вопрос как пришёл, OPT 4096, если он был в запросе), поэтому имена ставятся только зонам dnstt. Запрос не класса IN, не QUERY или с версией EDNS не 0 идёт в бэкенд, как раньше.
- Тесты: ответы вершины, в том числе разобранные dnspython; SOA через настоящий фронт рядом с бэкендом dnstt с dnsauth required.
